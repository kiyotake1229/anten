# 暗転 開発ドキュメント管理ルール

このファイルは、docs/ フォルダにドキュメントを追加する際のルールを定めています。

ドキュメント一覧: docs/manager/docs.json

---

## 1. 命名規則

```
YYYYMMDD_種類_連番_場所_内容.拡張子
```

例: `20261013_BUG_0002_GAME_忍び列が壁で止まらない.md`

- **YYYYMMDD**: 作成日
- **種類**: 案件の種類（下記参照）
- **連番**: 4桁の連番（0001〜9999）
- **場所**: 対象システム（下記参照）
- **内容**: 内容がわかる日本語名

---

## 2. 種類（Type）略語一覧

| 略語 | 意味 | 説明 |
|------|------|------|
| INQ | Inquiry | お問い合わせ対応・調査 |
| BUG | Bug Fix | バグ修正 |
| FIX | Fix | 軽微な修正 |
| NEW | New Feature | 新規開発 |
| ENH | Enhancement | 機能改善・拡張 |
| SEC | Security | セキュリティ対応 |
| DOC | Document | ドキュメント作成 |
| REF | Refactor | リファクタリング |
| DPL | Deploy | デプロイ関連 |
| RPT | Report | 報告書・見積書 |
| UPD | Update | 既存機能の更新 |

---

## 3. 場所（Category）略語一覧

| 略語 | 対象システム |
|------|-------------|
| ALL | プロジェクト全体 |
| APP | 画面・演出・音・保存（`index.html` のうち GAME 以外。HTML・CSS・HUD・タイトル・リザルト・設定・粒子・WebAudio・localStorage） |
| GAME | ゲームの規則（`index.html` 内の「生成（難易度の式）」「物理」「得点」「まぶた」の節。速度・間隔・隙間・据え列/移り列/忍び列の決まり・当たり判定・暗列の判定・自動検証ボット） |
| PWA | PWA と公開用の素材（`manifest.json` / `sw.js` / アイコン / `tools/make-icons.sh`） |
| IOS | iOS アプリ（`ios-app/`。未作成） |

GAME を変えて列の並びが変わる（同じ日付で別の「今日の暗転」になる）ときは、文書に「日替わりの配置が変わる」と必ず書く。

---

## 4. 連番管理

- 連番は全ドキュメント共通で管理（場所や種類で分けない）
- 関連案件は同じ連番を使用するか、ファイル内で関連番号を記載
- 次の連番は `docs/manager/docs.json` の `next_no` で確認

### docs.json の更新（重要）

ドキュメントを作成・編集した後は、必ず以下のコマンドを実行すること:

```bash
bash docs/manager/generate_docs_json.sh
```

---

## 5. ファイル配置

すべてのドキュメントは `docs/` 直下に配置する。サブフォルダは使用しない。

管理用ファイル:
- `docs/README.md` — このファイル（ルール説明）
- `docs/manager/` — 管理スクリプト・データ

---

## 6. 必須記載項目

### (1) ヘッダー情報
管理番号、種類、対象システム、作成日、関連案件

### (2) 概要
何についてのドキュメントか（1〜3文）

### (3) 対象ファイル
関連するソースコードファイルのパスを記載

### (4) 変更内容（変更の場合）
何をどう変更したか

### (5) 確認URL（動作確認が必要な場合）

| 環境 | URL |
|------|-----|
| ローカル | http://127.0.0.1:8795/ （このフォルダで `python3 -m http.server 8795 --bind 127.0.0.1`） |
| 開発確認用 | Claude Artifact の URL（README に記載） |
| 本番 | GitHub Pages の URL（公開後） |

### (6) 作業概要と概算費用（作業が発生する場合）

| 項目 | 内容 | 工数 |
|------|------|------|
| 調査 | ... | Xh |
| 実装 | ... | Xh |
| テスト | ... | Xh |
| 合計 | | Xh（Y人日） |

- 工数は時間（h）で書き、8h = 1人日で換算する
- 人日単価は未設定のため、金額は書かない

---

## 7. gitコミット時のルール

まだ git 管理していない（GitHub Pages で公開するときに始める）。始めたら下のルールでコミットする。

| 変更種類 | ドキュメント | 必須度 |
|----------|-------------|--------|
| 新機能追加 (NEW) | 必須 | ◎ |
| バグ修正 (BUG) | 必須 | ◎ |
| 機能改善 (ENH) | 必須 | ◎ |
| セキュリティ対応 (SEC) | 必須 | ◎ |
| 軽微な修正 (FIX) | 推奨 | ○ |
| リファクタリング (REF) | 状況による | △ |

```
[#連番] 変更内容の要約

- 変更ファイル一覧
- 関連ドキュメント: docs/YYYYMMDD_TYPE_NNNN_CAT_タイトル.md
```

ドキュメント不要の場合: `[no-doc] タイポ修正: path/to/file`
