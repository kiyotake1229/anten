# 岩崎さんへ — 「暗転」iOSアプリ ビルド・申請手順

岩崎さん

「触ると動ける。でも見えない」をルールにした落下回避ゲーム「暗転（あんてん）」の iOS プロジェクトです。
**Xcode で開いてビルド → App Store 申請** まで進められる状態になっています。

必要な作業は大きく2つです。

1. Xcode で開いて、署名（Team）を自社アカウントに設定してビルド → 3章
2. App Store Connect にアップロードして審査に提出 → 4章

申請時に入力するアプリ名・説明文・キーワードなどは、4章に**下書きを用意してあります**。
そのまま使っていただいても、修正いただいても構いません。

ご不明な点があればお知らせください。

## 1. アプリ概要

| 項目 | 内容 |
|------|------|
| アプリ名 | 暗転（あんてん） |
| Bundle ID | `work.ltv.anten` |
| 構成 | Capacitor 7（アプリ本体 `index.html` を同梱した形式。通信して Web サイトを表示する作りではありません） |
| 対応 | iPhone（縦固定）/ iPad |
| 通信 | **なし**（完全オフライン動作。外部フォントも使いません） |
| データ | **端末内のみ**（アプリ内の保存領域）。外部送信・収集は一切なし |
| ネイティブ機能 | 触覚フィードバック（閉眼・暗列・ヒヤリ・死亡・ベスト更新）、ローカル通知（毎朝8時の「今日の暗転」。設定で ON/OFF、初期は OFF）、ステータスバーの明暗の切り替え |
| スクリーンショット | `screenshots/` に4サイズ×5枚を用意済み（4章） |
| サポートURL | https://kiyotake1229.github.io/anten/support.html |
| ビルド確認 | GitHub Actions（`.github/workflows/ios-build.yml`）で、署名なしのビルドが通ることを確かめています（macos-26・Xcode 26。2026-10-13 成功） |

### ゲームの内容（審査担当者に説明するときの要点）

- 白く光る点（熾火）を、上から落ちてくる黒い列の隙間に通し続ける
- **触れている間だけ動けるが、触れた瞬間にまぶたが閉じて画面が真っ暗になる。離すと見えるが動けない**
- 閉じたまま列を抜けると得点が +2 → +3 → +4 → +5 と増える
- 目を閉じている間だけ動く「忍び列」、左右が逆になる「鏡の列」、隙間が2つの「選択列」
- 日付で決まる同じ配置に1日3回挑む「今日の暗転」（自己ベストの軌跡が一緒に走る）
- 段位（6段階）と、累計で変わる熾火の色（5段階）

## 2. 必要な環境

- macOS（Xcode 26 が動くバージョン）
- **Xcode 26**（Capacitor 7 は iOS 27 SDK の UIScene 必須化に未対応のため、Xcode 27 ではなく 26 でビルドしてください）
- Node.js 18 以降
- CocoaPods（`brew install cocoapods`）

## 3. ビルド手順

このフォルダ（`ios-app/`）で、以下を順に実行してください。

```bash
# 1) 依存パッケージを取得（node_modules は Dropbox を軽くするため消してあります）
npm install

# 2) アプリ本体（../index.html など）を www/ にコピーし、iOS プロジェクトに取り込む（pod install も走ります）
npm run sync

# 3) Xcode で開く
npm run open
```

> **注意**: `npm run open` は `ios/App/App.xcworkspace` を開きます。手で開く場合も必ず `.xcworkspace` の方を開いてください（`.xcodeproj` ではありません）。

### Xcode 上での設定

1. 左ペインで **App** を選択 → **Signing & Capabilities** タブ
2. **Team** に自社の Apple Developer アカウントを選択（"Automatically manage signing" は ON）
3. 必要に応じて **Bundle Identifier** を自社のものに変更（初期値は `work.ltv.anten`）
4. **General** タブで **Version**（例: 1.1.0）と **Build**（例: 1）を設定
5. **Push Notifications** の Capability は不要です（ローカル通知のみ）

### 動作確認

上部のデバイス選択から実機またはシミュレータを選び ▶ で起動。最初の画面で触れると真っ暗になり、離すと見える、が確かめられれば正常です。音は本体の消音スイッチを切ると鳴ります。

## 4. App Store 申請

1. Xcode: **Product → Archive**
2. Organizer が開いたら **Distribute App → App Store Connect** でアップロード
3. [App Store Connect](https://appstoreconnect.apple.com) でアプリ情報を入力して審査提出

### 申請情報（下書き）

**アプリ名（30字以内）**
```
暗転 - 触ると見えなくなる回避ゲーム
```

**サブタイトル（30字以内）**
```
見るか、動くか。親指ひとつで選び続ける
```

**説明文**
```
触ると動ける。でも見えない。
白く光る点を、落ちてくる黒い列の隙間に通し続ける、新感覚の回避ゲームです。

指で触れている間だけ動けます。けれど触れた瞬間にまぶたが閉じて、画面は真っ暗に。
指を離せば見えます。でも、動けません。
「見るか、動くか」を親指ひとつで選び続けてください。

■ 閉じたまま抜けると得点が増える
前の列を抜ける前から目を閉じっぱなしで次の列を抜けると「暗列」。+2、+3、+4、+5 と増えていきます。

■ 暗闇の中の手がかり
閉じた瞬間に見えていた列が青白い残像として残ります。列を抜けるたびに左右から音が鳴り、閉じている時間は熾火のまわりの輪で分かります。

■ 読みが深まる列
目を閉じている間だけ動く「忍び列」。閉じている間だけ左右が逆になる「鏡の列」。隙間が2つある「選択列」。

■ 今日の暗転
日付で決まる同じ配置に、1日3回だけ挑めます。2回目からは自己ベストの軌跡が一緒に走ります。記録は共有できます。

■ 段位と熾火
自己ベストで段位が上がり、遊んだ累計で熾火の色が白から蒼、金、紅、虹へと変わります。

■ 理不尽な配置はありません
動かないと抜けられない列は2本までで、3本目は必ず動かなくていい列。隙間は必ず通れる幅。プログラムが自動で何千列も走って確かめています。

完全オフライン動作。データは端末内にのみ保存され、外部に送信されません。
```

**キーワード（100字以内・カンマ区切り）**
```
回避,避けゲー,暗闇,反射神経,片手,新感覚,ハイスコア,日替わり,カジュアル,ミニゲーム,暇つぶし,集中
```

**カテゴリ**
- プライマリ: ゲーム（サブカテゴリ: アクション / カジュアル）
- セカンダリ: エンターテインメント

**年齢制限**: 4+

**プロモーション用テキスト（170字以内・任意）**
```
触ると動ける。でも見えない。見るか動くかを親指ひとつで選び続ける、新感覚の回避ゲーム。1日3回だけの「今日の暗転」で記録を競おう。
```

### プライバシー情報（App Store Connect「App のプライバシー」）

- **データを収集しません** を選択してください。
- 理由: 本アプリは通信機能を持たず、すべてのデータは端末内にのみ保存されます。アナリティクス・広告・トラッキングは一切ありません。
- プライバシーポリシーの URL: `https://kiyotake1229.github.io/anten/support.html#privacy`
- アプリには `PrivacyInfo.xcprivacy`（プライバシーマニフェスト）を同梱済みです（トラッキングなし・収集データなし。UserDefaults とファイルの時刻の参照理由を申告）

### サポートURL
```
https://kiyotake1229.github.io/anten/support.html
```

### 輸出コンプライアンス

暗号化は使っていません（`Info.plist` に `ITSAppUsesNonExemptEncryption = NO` を設定済み）。アップロード時の質問には「いいえ」で進めます。

## 5. 審査で見られやすい点

Apple ガイドライン **4.2（最低限の機能）** について、本アプリは以下を満たしています。申請時の備考欄（審査メモ）に書くと安全です。

- 完全オフラインで動作する自立したゲーム（Web サイトの単なる表示ではない）
- 端末内に記録（ベスト・累計・日替わりの記録）を保存し、継続的に遊ぶ設計
- ネイティブ機能: 触覚フィードバック、ローカル通知、ステータスバーの切り替え

審査メモの例:
```
This is a self-contained offline arcade game. While the finger touches the screen the player can move but the "eyelids" close (the screen goes dark); releasing opens the eyes but stops movement. Scores, daily records and settings are stored on device only. Native features: haptic feedback, local notifications (optional morning reminder), status bar styling. No network access, no accounts, no data collection.
```

**画面が真っ暗になるのは仕様です。** 審査担当者が「触ったら画面が消えた」と誤解しないよう、上のメモに書いておいてください。

## 6. アプリ内容を修正したい場合

アプリ本体は 1つ上のフォルダの `index.html` です。修正後、このフォルダで:

```bash
npm run sync
```

を実行すると iOS プロジェクトに反映されます。その後 Xcode で再ビルドしてください。

ネイティブ機能のコードは `index.html` の「ネイティブ連携」の節にまとまっています（通知の予約 `notifyApply()`、触覚 `haptic()`、ステータスバー `statusBarDark()`）。
